# 绘本审核与积分奖励后台

## 入口

- 管理员账号头像菜单、上传页的“管理后台”入口。
- `/admin/books`：待审核、已通过、已驳回列表，搜索、分页、逐页预览、通过和驳回。
- `/admin/rewards`：奖励结果，筛选已发放、待完成、失败；重试未完成的奖励。
- 非管理员无法进入前端路由；后端 `/admin/*` 与旧审核接口均校验管理员权限。

## 作者端

“我的绘本”分别显示审核状态与私有状态，并展示已获积分、驳回原因。点击奖励进入
`/member/points-history?bookId=...`，只查询当前登录用户对此绘本的奖励流水。
修改标题、描述或页面会重新进入审核；已发放奖励保留，不重复发放。

## 后端配套

后端项目为 `D:/ranran_program/clouddrawing`。

- Book 新增审核人、时间、驳回原因、奖励状态、发放时间和冻结的奖励数额。
- User 的奖励绘本 ID 与余额增量在同一次原子更新中写入，避免重复加积分。去重字段不默认返回。
- 流水使用由绘本 ID 派生的固定 ID，重试不会重复创建流水。
- 流水与绘本奖励标记完成后才显示“已发放”；中途失败可安全重试，补齐记录。
- 不依赖 MongoDB 多文档事务。不重复发放历史已发奖励，也不自动补发历史已发布但无奖励记录的绘本。
- 奖励规则沿用服务器配置；用户端不展示每页奖励数额。
- 作者编辑和个人资料更新使用字段白名单，不能写审核结果、积分或奖励去重字段。

## 部署和验证

先部署后端，再部署前端；无需新增依赖。新字段随文档写入，不批量修改历史作品。

后端检查：`npx tsc --noEmit`，`node --test scripts/test-book-review.cjs scripts/test-book-source.cjs`。

浏览器通过模拟接口验证审核、驳回、失败重试、作者奖励明细、手机布局和普通账号路由拦截。
测试不向真实用户作品或余额写入数据；真实数据库验证应使用专用测试账号与绘本。
